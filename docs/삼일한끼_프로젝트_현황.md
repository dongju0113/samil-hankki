# 삼일한끼 프로젝트 현황 (D-4조)

최종 업데이트: 2026-10-05

## 서비스 한 줄 소개
2026 삼일회계법인 신입 연수 기간에, 일정·관심사가 맞는 동기끼리 점심 조를 자동으로 짜 주는 웹앱.

## 현재 기술 스택
- Frontend: HTML 파일 1개(`index.html`) + Tailwind CSS(CDN) + 순수 자바스크립트
- Framework: 없음 (단순함 유지를 위해 React 등 사용 안 함)
- Database: Supabase (CDN `<script>`로 연결. 설정 방법: `docs/Supabase_설정_가이드.md`, SQL: `supabase/`)
- 매칭 자동 실행: Vercel Cron Jobs + 서버리스 함수(`api/cron-match.js`)
- Code Repository: GitHub `dongju0113/samil-hankki` (공개, https://github.com/dongju0113/samil-hankki)
- Deployment: Vercel — **https://samil-hankki261005.vercel.app** (GitHub에 올리면 자동 배포)
- 확인 코드 메일: Gmail `samilhankki@gmail.com` (`api/send-code.js`)
- 데이터 저장: Supabase 중앙 저장 (localStorage는 "이 기기에서 내 이메일·코드 기억" 용도로만 사용)

## 화면 흐름 (2026-10-06 개편, 디자인: 팀원 samil-d4 버전)
1. 시작 페이지: "오늘 점심, 누구랑 먹지?" + 슬롯머신(돌려돌려 한끼) + 실시간 "매칭 대기 중 N명"
2. 1단계 기본 정보: 이름, 출생연도·성별(필수), 이메일, 소속 부문, MBTI(16), 원하는 조원 성별·부문(복수, 상관없음), 희망 인원, 정보 사용·공유 동의
3. 2단계: 가능한 날짜·시간 (오늘 포함 7일) → [신청하기] → 축하 효과(입자·코드 굴리기·완료 알림) + 확인 코드 메일
4. 내 결과 확인: 이메일 + 코드 → 조 정보(조원 이름은 최*주처럼 가림, 이메일·출생연도·성별·부문·MBTI), 참석/패스
5. 운영자 콘솔(Supabase 로그인 + 운영자 등록 계정): 매칭 설정, 수동 매칭, 조원 이동, 강제 확정, 해체

## 확정된 결정 사항
- 이메일: 사내메일 미발급으로 naver.com / gmail.com 선택. 코드의 `EMAIL_DOMAINS` 목록만 바꾸면 pwc.com 추가 가능
- 일러스트: 실존 인물·방송 포스터 사용 안 함. 직접 그린 SVG, 얼굴은 단순한 스타일(웃는 눈 + 볼터치)
- 일정표: 고정 날짜 대신 매일 "오늘부터 2주"를 자동 표시 (운영자가 날짜를 정할 필요 없음)
- 매칭 방식: 매일 22:00~22:59(한국 시간, Vercel 무료 플랜)에 "아직 조가 없는 사람만" 자동 매칭. 이미 만들어진 조는 건드리지 않음
- 매칭 점수(두 사람 궁합, 100점): MBTI 50 (궁합표 `matching.js`의 MBTI_TABLE — 팀 궁합표 받으면 채움) + 성별 25 + 부문 25 (서로 원하는 성별·부문에 맞으면 각 12.5점씩). 관심사·음식 등 예전 항목은 삭제
- 본인 확인: 로그인 없이 이메일 + 6자리 코드. 같은 기기에서는 자동 기억, "이 기기에서 내 정보 지우기" 제공
- 결과 전달: 웹앱에서 직접 확인. 신청 완료 시 확인 코드를 이메일로도 발송(`samilhankki@gmail.com`, `api/send-code.js`)
- 참석 응답: 각자 [참석할게요] / [이번 조는 패스]
  - 조원 전원 참석 → 확정
  - 응답 마감(점심 시작 N분 전, 기본 60분)까지 무응답 → 참석으로 간주
  - 패스 → 조에서 빠지고 다음 매칭 대기, 같은 조원과는 다시 묶이지 않음
    (예외: 조를 짜고 남은 1~2명을 기존 조에 붙이는 단계는 이 조건을 보지 않음 — 원래 규칙. 고칠지 결정 필요)
  - 패스로 1명만 남으면 그 사람도 대기로
- 운영자 권한: 평소엔 손대지 않음. 예외 처리용으로 조원 이동, 강제 확정, 해체, 지금 매칭 실행

## 발표용 AI 활용 사례 메모
- 매칭 방식 5가지(본인 선택형, 테이블 참여, 일괄 편성, 테마 모집, 랜덤)를 AI와 비교 후, 기간·팀 역량을 고려해 "매일 밤 자동 매칭 + 본인 참석/패스"로 결정
- 연예인 얼굴 사용 요청 → 초상권 문제를 확인하고 오리지널 일러스트로 방향 전환
- 운영자 버튼이 안 눌리는 문제 → 원인(미리보기 환경에서 브라우저 기본 팝업 차단) 파악 후 페이지 안 팝업으로 수정
- "300~400명이 각자 쓰면 데이터가 각 기기에만 남는다"는 문제를 팀이 직접 발견 → 이메일 + 코드 본인 확인 + Supabase 중앙 저장으로 설계
- 데모(각 기기 저장) → 실제 서비스로 전환하면서, AI에게 "보안 규칙·본인 확인 함수·운영자 로그인"을 단계별로 요청하고 Supabase 화면 작업은 비개발자용 안내를 받아 직접 수행
- 자동 매칭 서버를 만들 때 매칭 규칙을 한 파일로 모으고, 바꾸기 전·후 결과를 무작위 400세트로 비교해 규칙이 그대로인지 검증
- 고정 날짜표 대신 "접속한 날부터 2주"로 바꾸자는 아이디어를 팀이 제안 → 운영자 설정 없이 해결
