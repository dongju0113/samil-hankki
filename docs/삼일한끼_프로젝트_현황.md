## 기술 구성
- 화면: HTML 한 파일(`index.html`) + Tailwind CSS(CDN) + 순수 자바스크립트 (빌드 도구 없음)
- 매칭 규칙: `matching.js` 한 파일 — 화면(운영자 "지금 매칭")과 서버(자동 매칭)가 같이 사용
- DB: Supabase (RLS 보안 규칙, 신청자는 함수로만 접근). SQL: `supabase/01~08`
- 배포: Vercel (GitHub에 올리면 자동 배포), 서버 함수 `api/`
- 자동 매칭: Vercel Cron 매일 22:00대(KST) + 23:00대 추가 메일 발송
- 메일: Gmail SMTP (`samilhankki@gmail.com`, 앱 비밀번호는 Vercel 환경변수에만)
- 검사: `node tests/run-all.cjs` (약 200개 항목, 통과해야 GitHub에 올림)

## 화면 흐름
1. **시작 페이지**: "오늘 점심, 누구랑 먹지?" / "AI 알고리즘이 잘 맞는 한 끼 메이트를 매칭" / "삼일한끼로, 삼일과 함께" + 3D 슬롯머신(레버를 아래로 당겨야 돎) + 실시간 "매칭 대기 중 N명"
2. **1단계 – ① 내 정보**: 이름, 출생연도, 성별, 이메일(naver/gmail), 소속 부문(Assurance·Tax·Deal·AX), MBTI(E/I → S/N → T/F → J/P 4번 선택)
   **② 원하는 조원**: 원하는 성별·부문(복수, 전부 고르면 "상관없음"), 희망 인원(2명 / 3~4명 / 5~6명), 정보 사용·공유 동의
   - 질문은 하나씩 나타남. 휴대폰은 커서 자동 이동 없음(입력 꼬임 방지)
3. **2단계**: 점심 시작 시간 11:30 / 12:00 / 12:30 / 13:00 × 오늘 포함 7일 (드래그로 여러 칸 선택, 휴대폰 포함) → [신청하기]
4. **신청 완료**: 축하 효과 + 6자리 확인 코드 + 확인 코드 메일(입력 정보 전체 포함)
5. **내 결과 확인**: 이메일 + 코드 → 조 정보(조원 이름은 홍*동처럼 가림, 이메일·출생연도·성별·부문·MBTI), 연락 담당, [참석할게요]/[이번 조는 패스], [내 신청 정보 수정하기]
6. **운영자 콘솔**(오른쪽 아래 자물쇠): 지금 매칭, 샘플 30명, 조원 이동, 강제 확정, 해체, 초기화, 설정

## 매칭 규칙
- **대상**: 아직 조가 없는 사람(+ 응답 마감 후 풀려난 사람). 이미 만들어진 조는 건드리지 않음
- **시간**: 같은 시작 시간을 고른 사람끼리만. 응답 마감(점심 60분 전)이 지난 칸은 제외
- **희망 인원**: ① 모든 조원의 희망 인원에 맞게 조를 만들고 → ② 희망이 맞는 기존 조에 합류 → ③ 그래도 남은 사람끼리 희망에 가장 가까운 크기로 (최대 6명)
- **궁합 점수(두 사람, 100점)**: MBTI 50(팀 궁합표의 절반) + 성별 25 + 부문 25 (서로 원하는 성별·부문에 맞으면 각 12.5점, "상관없음"은 누구든 맞음)
- **패스**: 조에서 빠지고 다음 매칭 대기. 같은 사람과 다시 만날 수 있음

## 참석·확정 규칙
- 응답 마감(점심 60분 전)까지 [참석할게요]를 누른 조원끼리만 만남 (예: 6명 중 4명 → 4명)
- 마감 전 전원 참석 → 바로 확정 / 운영자 강제 확정 → 전원 확정
- 마감 후 참석 안 누른 사람은 자동 취소, 참석 1명 이하면 조 취소 → 다른 가능한 시간이 있으면 다음 매칭 대상
- **연락 담당**: 조마다 1명 무작위 지목. 담당이 빠지면(패스·이동·재신청) 남은 조원 중 다시 지목

## 메일
- 신청 완료: 확인 코드 + 입력 정보 전체 (실패 시 화면에 이유 표시: gmail_login / gmail_limit / timeout)
