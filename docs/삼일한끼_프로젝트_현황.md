# 삼일한끼 프로젝트 현황 (D-4조)

최종 업데이트: 2026-10-05

## 서비스 한 줄 소개
2026 삼일회계법인 신입 연수 기간에, 일정·관심사가 맞는 동기끼리 점심 조를 자동으로 짜 주는 웹앱.

## 현재 기술 스택
- Frontend: HTML 파일 1개(`index.html`) + Tailwind CSS(CDN) + 순수 자바스크립트
- Framework: 없음 (단순함 유지를 위해 React 등 사용 안 함)
- Database: Supabase (CDN `<script>`로 연결. 설정 방법: `docs/Supabase_설정_가이드.md`, SQL: `supabase/`)
- 매칭 자동 실행: Vercel Cron Jobs + 서버리스 함수(`/api` 폴더) 예정
- Code Repository: GitHub
- Deployment: Vercel
- 데이터 저장: Supabase 중앙 저장 (localStorage는 "이 기기에서 내 이메일·코드 기억" 용도로만 사용)

## 화면 흐름
1. 시작 페이지: "삼일한끼" 일러스트(감나무 아래 점심상, 삼일회계법인 명함을 주고받는 두 신입), [점심 한끼 함께해요!], [내 결과 확인하기]
2. 설문 5단계: 기본 정보 → 가능한 일정 → 음식·인원·분위기 → 관심사·우선 조건 → 확인 및 제출
3. 신청 완료: 6자리 결과 확인 코드 발급
4. 내 결과 확인: 이메일 + 코드 입력 → 조 정보, 참석/패스 선택
5. 운영자 콘솔(Supabase 로그인 + 운영자 등록 계정): 자동 매칭 설정, 수동 매칭, 조원 이동, 강제 확정, 해체

## 확정된 결정 사항
- 이메일: 사내메일 미발급으로 naver.com / gmail.com 선택. 코드의 `EMAIL_DOMAINS` 목록만 바꾸면 pwc.com 추가 가능
- 일러스트: 실존 인물·방송 포스터 사용 안 함. 직접 그린 SVG, 얼굴은 단순한 스타일(웃는 눈 + 볼터치)
- 매칭 방식: 매일 정해진 시각(기본 22:00)에 "아직 조가 없는 사람만" 자동 매칭. 이미 만들어진 조는 건드리지 않음
- 매칭 점수: 관심사·음식·예산·분위기·매운맛 + 각자 고른 우선 조건(먼저 고른 조건 가중치 4, 두 번째 3)
- 본인 확인: 로그인 없이 이메일 + 6자리 코드. 같은 기기에서는 자동 기억, "이 기기에서 내 정보 지우기" 제공
- 결과 전달: 이메일 발송 대신 웹앱에서 직접 확인 (이메일 알림은 Could Have)
- 참석 응답: 각자 [참석할게요] / [이번 조는 패스]
  - 조원 전원 참석 → 확정
  - 응답 마감(점심 시작 N분 전, 기본 60분)까지 무응답 → 참석으로 간주
  - 패스 → 조에서 빠지고 다음 매칭 대기, 같은 조원과는 다시 묶이지 않음
  - 패스로 1명만 남으면 그 사람도 대기로
- 운영자 권한: 평소엔 손대지 않음. 예외 처리용으로 조원 이동, 강제 확정, 해체, 지금 매칭 실행

## 다음 단계 (Supabase 연결)
※ 1~4는 코드 작업 완료(2026-10-05). Supabase 화면에서 SQL 실행·운영자 등록은 `docs/Supabase_설정_가이드.md` 참고
1. ✅ Supabase 표 만들기: 신청 응답(`applications`), 조(`groups`), 조원·참석 응답(`group_members`), 설정(`settings`), 운영자(`admins`)
2. ✅ 보안 규칙(RLS): 신청자는 저장만 가능, 전체 목록은 운영자 로그인만 조회
3. ✅ "이메일 + 코드가 맞을 때 본인 결과만 돌려주는 함수" 만들기 (참석/패스 포함, 10회 실패 시 15분 잠금)
4. ✅ 운영자 로그인을 Supabase 로그인으로 교체 (1234 방식 폐기)
5. Vercel 서버리스 함수 + Cron으로 매일 22:00(한국 시간, 설정값은 UTC 13:00) 자동 매칭
6. service_role key는 Vercel 환경변수에만 저장, 코드·GitHub에 절대 넣지 않음

## 남은 결정 사항
- 2단계 날짜표를 10/14 하루로 줄일지 여부
- 카카오톡 공유 시 "기본 브라우저로 열기" 안내 문구

## 발표용 AI 활용 사례 메모
- 매칭 방식 5가지(본인 선택형, 테이블 참여, 일괄 편성, 테마 모집, 랜덤)를 AI와 비교 후, 기간·팀 역량을 고려해 "매일 밤 자동 매칭 + 본인 참석/패스"로 결정
- 연예인 얼굴 사용 요청 → 초상권 문제를 확인하고 오리지널 일러스트로 방향 전환
- 운영자 버튼이 안 눌리는 문제 → 원인(미리보기 환경에서 브라우저 기본 팝업 차단) 파악 후 페이지 안 팝업으로 수정
- "300~400명이 각자 쓰면 데이터가 각 기기에만 남는다"는 문제를 팀이 직접 발견 → 이메일 + 코드 본인 확인 + Supabase 중앙 저장으로 설계
